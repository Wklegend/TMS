# قاعدة البيانات — Google Sheets الآن، MySQL لاحقًا

## التصميم
- قاعدة بيانات علائقية بالمعايير المعتادة: أسماء snake_case، جداول بصيغة الجمع، مفتاح أساسي `id` ثابت، مفاتيح أجنبية `*_id`، أعمدة تدقيق `created_at` / `updated_at`.
- جداول مرجعية `lk_*` لكل القيم الثابتة (الحالات، الأولويات، الأدوار…)، فلا تُكتب النصوص مكررة داخل الجداول.
- العلاقات المتعددة في جداول مستقلة (التطبيع): مراحل ومخرجات ومؤشرات المشاريع، بنود تحضير الدورات وتسجيلاتها، تذكيرات المهام وتبعياتها، الموظفون المكلفون بكل تكليف، روابط التكليفات والأفكار.
- سجل تغييرات موحّد `activity_log` لكل العناصر، وإعدادات التطبيق في `app_settings`.
- العمود `extra_json` يحفظ أي حقل جديد لم يُخصص له عمود بعد، فلا تضيع بيانات.
- «متأخرة» لا تُخزَّن؛ تُحسب من الموعد والحالة.

## الملفات
- `mysql-schema.sql` — إنشاء القاعدة في MySQL 8 (34 جدولًا، 44 مفتاحًا أجنبيًا، والجداول المرجعية مع قيمها). جُرّب تحميله على خادم MariaDB دون أخطاء.
- `data-dictionary.csv` — قاموس البيانات: كل جدول وعمود ونوعه ومفتاحه ووصفه. نفسه موجود في ورقة `_dictionary` داخل الشيت.
- `../google-sheets/Code.gs` — يبني الجداول نفسها داخل Google Sheets ويخدم الموقع.

الشيت وMySQL مولَّدان من تعريف واحد، فكل ورقة في الشيت تطابق جدولًا بالاسم والأعمدة نفسها.

## النقل إلى MySQL
1. على السيرفر: أنشئ قاعدة بترميز utf8mb4 ونفّذ `mysql-schema.sql`.
2. صدّر كل ورقة من الشيت كملف CSV (أو استخدم أمر الاستيراد في نسخة Laravel)، واستوردها إلى الجدول الذي يحمل الاسم نفسه. الأعمدة متطابقة.
3. الترتيب المقترح للاستيراد: الجداول المرجعية `lk_*`، ثم departments، people، ideas، projects، courses، tasks، assignments، ثم الجداول التابعة وactivity_log وapp_settings.
